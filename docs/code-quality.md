ESLintではブラウザー・Worker・Nodeのグローバルを広めに許可しています。これは既存コードを検査するための現状設定であり、実行環境をまたぐ誤った依存まで検出できる設定にはなっていません。未使用変数の大文字名などに例外もあるため、Lint成功を未使用コードの完全な除去と同一視しないでください。

`legacy/server/` のRust版は現行SaaSの実行経路から外しています。現在のCIにはRustのビルド、rustfmt、Clippyを含めておらず、旧版のコード品質や動作も同じ範囲で検証済みとはしていません。

## 構造面の改善対象

1. `cloudflare/map-app.mjs` は認証・ルーティング・資料・台帳・保存を多く持っています。HTTPの受付、業務処理、DBへの保存を機能単位で分け、共通の権限・保存検証を維持するのが次の分割対象です。
2. `frontend/src/console/team.jsx`、`registers.jsx`、`frontend/src/map/app.js` は大きなファイルです。表示部品だけでなく、データの取得・更新、条件の保存、操作状態を分ける余地があります。
3. マップはIIFEと `window.Factory...` の公開API・読み込み順に依存しています。将来のES Modules化は、Reactとの接続・CAD・WebMCPの互換性をテストしながら進める必要があります。
4. サーバーの検証は実行時の手書き検証です。API・保存モデル・画面の型と仕様のずれを減らす仕組みは、まだ十分ではありません。

ファイルを機能別ディレクトリへ移したことは、これらの責務分離を完了したことを意味しません。特定のアーキテクチャ名称やSOLID原則への全面準拠も、この段階では表明していません。

## コメントの方針

- 自作コードの説明は日本語で書きます。各モジュールの役割、呼び出し元との境界、保存・公開するデータの範囲を説明します。
- 複雑な処理には、設計理由、守る条件、失敗・再試行・競合時の扱いを残します。単純な代入や反復の逐語説明は増やしません。
- 外部との接点や共通処理には、必要に応じてJSDocで引数・戻り値・副作用を補足します。JSDocを付けたことだけで、型検査済みとは扱いません。
- 画面の入力制御とサーバーの権限検証、台帳の下書き変更とDBへの確定を、説明でも区別します。
- 不具合修正で残すコメントには、なぜ必要かと、回帰させたくない条件を書きます。実装と異なる古い説明も同時に更新します。
- 第三者ライブラリーの原本、ライセンス表記、生成物は翻訳・加筆しません。既に適用したDBマイグレーションは、説明の追加だけを目的として書き換えません。

今回のコメント整備では、変更前後のJavaScript / JSXの構文木と、説明用のdocstringを除いたPythonの構文木を比較し、実行する処理に変更がないことを確認しました。構文の一致は、外部規格への適合やコメントの内容の正しさを保証するものではありません。
