# 施設グループの業務管理

PlantDeskの「タスク」とNotionを使い、作業依頼から担当決定、実施、点検結果、引き継ぎまでを管理します。設備・図面・工事との関連は同じ作業に保持します。

## 業務画面の役割

- **ダッシュボード**：チーム全体の遅れ・担当未定・確認待ち・作業負荷を確認し、割り振りを調整します。
- **タスク**：日々の仕事を一覧・ボード・週間予定で進めます。点検・修理は「点検・保守」で絞り込み、周期の設定は「点検計画」、設備の次回点検日と実施済みの結果は「点検予定・履歴」から確認します。

一覧の担当・期限・優先度・状態を直接編集し、詳細やチェックリストは右側のペインで操作します。タスクと点検は同じデータを参照し、別画面への二重登録は不要です。

## 毎日の確認

1. Notionの業務ホームで、期限超過と今日までの作業を確認します。
2. 「受付・担当未定」で担当者と期限を決め、依頼元を残します。
3. 「確認・手配待ち」には、待っている相手・回答・次の確認日を記入します。
4. アプリの「先行作業待ち」「着手できる仕事」を使い、工程の順序を確認します。
5. 点検はアプリで結果を記録して完了します。異常があればフォロー作業も作れます。

## 案件と作業の関係

設備更新や修繕など、複数の作業がある仕事は案件を作成します。「タスク → 案件・改善」から、責任者・期間・目的と完了条件を設定できます。

- **案件**：複数の作業をまとめる単位です。中止を除いた作業の完了率、未完了数、期限超過を集計します。
- **親作業・子作業**：一つの仕事を細分化します。同じ案件に所属し、子作業が完了・中止してから親を完了できます。
- **先行作業**：作業の実施順序です。指定した先行作業がすべて完了すると、開始・完了できます。中止した先行作業を免除する場合は、関係を見直して保存してください。
- **完了条件**：何を確認できれば完了かを記入します。条件がある作業は、完了画面で確認済みにしてから保存します。

循環参照、存在しない関連先、案件が異なる親子関係は保存できません。先行作業や子作業の完了制御は、直接APIを呼ぶ場合やNotionから同期する場合も適用します。未完了の仕事が残った案件は完了にできません。案件の完了率は作業件数の比率で、工数で重み付けした値ではありません。

## Notionの画面構成

業務ホームは元の台帳を参照するリンクドビューで構成します。別の台帳へコピーして一覧を作る必要はありません。

| 表示 | 条件・用途 |
| --- | --- |
| 今日までに対応 | 未完了かつ期限が今日以前。期限の昇順 |
| 受付・担当未定 | 未完了かつ担当者が空欄 |
| 進行状況 | 未完了の作業を状態別のボードで表示。担当・案件・優先度で絞り込み |
| 確認・手配待ち | 手配待ちの理由と次の行動を確認 |
| 案件・改善プロジェクト | 責任者・期限・進捗・期限超過を確認 |
| 点検・工事の予定 | 7日以内に予定のある点検計画と、未完了工事の工程表 |
| 台帳と詳細設定 | 設備・工事・担当者・案件・作業・点検計画・点検履歴の元データ |

Notionの各案件ページにも、その案件だけの作業ボードを表示できます。作業ページは状態・担当・期限・優先度を固定表示し、関連先・点検結果・連携用の詳細はサイドバーへまとめます。JSONや内部IDは通常の一覧に出しません。

## 同期する項目

担当者・案件・設備・工事・点検計画・作業・点検履歴を同期します。案件、親作業、先行作業はNotionのリレーションとして保存し、依頼元・着手予定・完了条件も双方向に反映します。案件の進捗・未完了数・期限超過はアプリの作業から計算する項目です。

Notionから入力した内容が工程のルールに合わない場合は、同期設定の「要確認」に表示します。Notionのページ本文・コメントと、アプリの引き継ぎコメントは別々に保存します。アプリの履歴へ残す内容は、作業の「引き継ぎコメント」から記録してください。写真・PDF・図面の本体はアプリで閲覧します。

継続同期にはNotionの内部接続トークンを設定画面で登録する必要があります。最初に両側へ配置するサンプルと、その後の定期同期は別の処理です。接続状態と最終正常完了日時は「Notion同期」で確認します。

## サンプル

チーム管理が空の場合、「案件と工程のサンプルを追加」で案件3件・作業16件・担当者4名・点検計画1件を追加できます。設備と工事はそのまま保持します。案件には、配管更新の前工程と子作業、予防保全、省エネ改善の手配待ちの例を含めています。

担当者名簿は作業の割り振り用です。現在のSSOデモは利用者ごとにワークスペースを分離しており、名簿を追加してもログイン権限の招待にはなりません。Notionの共有はNotion側の権限で管理します。
