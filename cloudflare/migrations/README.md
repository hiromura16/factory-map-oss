# D1マイグレーションの役割

番号順に適用する、現行SaaSのDB変更です。適用済みファイルは変更せず、スキーマの変更には新しい番号のSQLを追加します。各ファイルの説明はここで管理します。

| ファイル               | 目的                                                                               |
| ---------------------- | ---------------------------------------------------------------------------------- |
| `0001_tenants.sql`     | 利用者、組織、所属、プラン、台帳のリビジョンと監査履歴の基礎                       |
| `0002_scim.sql`        | SCIMでの利用者の関連付け、状態・バージョン、操作履歴と競合検出                     |
| `0003_map_product.sql` | 利用者別のデモアカウント、個人設定、資料・チャンク、バックアップ、APIトークン      |
| `0004_work_events.sql` | 工事の変更履歴と、導入時点の既存工事のbaseline記録                                 |
| `0005_team_tasks.sql`  | タスクの変更履歴と、その工事履歴とは独立した検索用インデックス                     |
| `0006_notion_sync.sql` | 暗号化した接続設定、定期実行、実行権・世代、再開位置、同期レコードの対応と実行履歴 |

台帳全体は `organizations.state_json` に保存しています。設備やタスクのレコードごとに独立した正規化テーブルを持つ設計ではありません。履歴・資料・設定・同期制御は別テーブルで管理します。[アーキテクチャ](../../docs/architecture.md)も参照してください。

資料の内容は `map_file_chunks` に保存します。R2への保存は現在の実装には含まれません。工事・タスクの履歴は削除前の内容と資料IDを残し、通常の台帳更新と同時に保存します。

適用方法は[Cloudflareへの配置](../../docs/cloudflare.md)、保存処理の入口は [`map-app.mjs`](../map-app.mjs) を参照してください。本番への適用前に、一時DBとバックアップを用意して確認します。
